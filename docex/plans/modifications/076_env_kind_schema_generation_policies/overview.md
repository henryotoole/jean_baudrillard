# Mod 076 — Engine `env:` `kind` schema + generation policies

Part of the [envmageddon campaign](../../campaigns/003_envmageddon/implementation_plan.md)
(step 2, mod 1 of 11). Foundation layer: teach the transfer tables the
three-`kind` engine-`env:` schema and the new `generation_policies:` section,
and add the pure value generator. No compiler *resolution* behavior changes yet
(that is Mod 077) — this mod is data model + loader + validation + the bundled
table + the generator + the `example.env` reshape.

## Why

`config_and_secrets.md` splits every env-tier value into three categories (TTE /
secret / config) by **provenance**. At the engine level that provenance is
declared by a per-variable **`kind`** on the engine's `env:` block
(`transfer_tables.md § Anatomy of a Role Definition`):

| kind | meaning | stored |
| ---- | ------- | ------ |
| `fixed` | doctrine-fixed literal (`value:`), inlined at compile | nowhere |
| `minted` | generated by docex per a `generation_policy` (`policy:`) | TTE store |
| `secret` (default) | operator-supplied | secrets file / SSM |

Today `EngineEntry.env` is `dict[str, str]` (key → description) and postgres'
`env:` block is `{POSTGRES_USER: "desc", POSTGRES_PASSWORD: "desc"}`. This mod
turns those descriptions into kind-tagged specs, collapses `POSTGRES_USER` to a
`fixed` literal (`appuser`) and `POSTGRES_PASSWORD` to a `minted` value governed
by a new `password` generation policy.

A minted value needs a *generator*, which is a different surface from the naming
`apply_policy` *formatter* — so mint rules live in a sibling top-level
`generation_policies:` block (`{length, alphabet}`), never inside
`naming_policies:` (keeps the two load-time allowlists clean).

## Scope

**In:** the `kind` schema on `EngineEntry.env`; scalar-shorthand back-compat
(`KEY: "desc"` == `{kind: secret, desc}`); `generation_policies:` section +
`GenerationPolicy` type + deep-merge + validation; `cicl/generate.py` (pure
CSPRNG generator, `url_safe`/`alnum` alphabets); rewrite postgres `env:`;
reshape `emit_example_env` to a **secrets-only keys manifest**; update the two
other `EngineEntry.env` readers (`roles/`).

**Out:** compile-time `$[VAR]` inlining of `fixed` vars (Mod 077); anything that
*calls* `generate()` (aggregation, Mod 080); the `config:` block (Mod 078).
The generator lands here (unit-testable in isolation) but is not yet wired to a
caller.

## Doctrine anchors

- `transfer_tables.md § Anatomy of a Role Definition` — the `env:` schema (scalar shorthand + full form), the postgres walking example, and the "kind: fixed inlined / minted+secret pass-through" rule.
- `transfer_tables.md § Generation Policies` — the `generation_policies:` schema, the shipped `password` policy, and why `url_safe` is load-bearing.
- `transfer_tables.md` validation rules 13 (minted `policy:` references a defined generation policy) + 14 (fixed⇒`value` no `policy`; minted⇒`policy` no `value`).
- `config_and_secrets.md § TTE Vars` — TTE = `kind: minted`; postgres mints only `POSTGRES_PASSWORD`.
- `cicl.md` line 392 — `example.env` is a committed keys-only manifest derived from core `secrets:` + backing `kind: secret` env vars + doctrine-injected keys.
