# Mod 161 — `docex docs adr`: ADR index generation

## Goal

Add the third `docex docs` subcommand: deterministic, idempotent regeneration of
the two ADR index files (`plans/design/adr_index.md`, `plans/design/adr_active.md`)
from the ADR source files under `plans/design/adrs/`. Fold a **staleness** check
into `docex docs check` (and the `docex check` gate) so a hand-edited or forgotten
index is caught as a blocking error — consistent with the anti-drift purpose of
`docs check`.

## Design source of record

- `doctrine/practices/adrs.md` § ADR Format (frontmatter schema) and § ADR Index
  (the exact two tables + columns). This is the rule; docex aligns to it.
- Mod 160's group under `docex/src/docex/docs/` (`standard_set.py`, `scaffold.py`,
  `check.py`, `__init__.py`) and the dispatcher in `docex/src/docex/__main__.py`.

## Behavior

### `docex docs adr`

Reads every `*.md` file directly under `plans/design/adrs/`, parses each file's
YAML frontmatter into a canonical `Adr` record, and regenerates both index files:

- **`adr_index.md`** — ALL ADRs, sorted by id:
  `| ADR ID | Title | Status | Date | Supersedes | Superseded By |`
- **`adr_active.md`** — ADRs that are `accepted` AND not superseded, sorted by id:
  `| ADR ID | Title | Date | Supersedes |`

Each generated file carries a first-line HTML-comment marker:
`<!-- generated by \`docex docs adr\` — do not edit by hand -->`, then the `#`
heading, then the table. The command overwrites whatever the scaffold stub laid
down. It is **deterministic** (stable sort by id) and **idempotent** (running
twice produces byte-identical files). Prints which files were (re)written.

Frontmatter fields consumed: `id`, `title`, `status`, `date`, `supersedes`,
`superseded-by`. (`tags` is parsed but not rendered in either index.)

### Design decisions

1. **"Active" filter** = `status == "accepted"` **and** `superseded-by` is empty.
   `status == accepted` already excludes `proposed`/`rejected`/`superseded`/
   `deprecated`; the empty-`superseded-by` guard additionally drops an ADR whose
   frontmatter says `accepted` but which another ADR has already superseded
   (inconsistent-but-defensive). The `supersedes` column renders the id list the
   ADR supersedes; `superseded-by` renders the id list that superseded it. Empty
   lists render as an empty cell.

2. **Stable id sort.** IDs are doctrine-format zero-padded strings (`0004`).
   Sort key is numeric when the id is all digits, else the raw string, so a
   mixed/legacy id set still sorts total-order-stably. The frontmatter `id` is
   authoritative (not the filename).

3. **One canonical render, shared with scaffold.** The render functions live in
   the new `adr.py` and are the single source of truth for the two files' exact
   bytes. Mod 160's `scaffold.py` currently hard-codes stub strings for
   `adr_index.md`/`adr_active.md`; those two stub entries are re-pointed to
   `render_index([])` / `render_active([])` so a **freshly-scaffolded tree is
   already byte-identical to a `docs adr` run over an empty ADR set**. This keeps
   the shared-canonical-definition discipline (scaffold and adr/check cannot
   disagree on the empty-index bytes) and, critically, means the new staleness
   gate passes on a fresh scaffold with no ADRs.

4. **Staleness folded into `docs check`** (deliberately included — wiring is
   clean). A pure `adr_index_drift(project_root)` regenerates both indexes in
   memory and diffs against on-disk content; any difference is a problem string.
   It is called from BOTH `check_docs` (standalone `docex docs check`) and
   `_gate_docs` (the `docex check` pipeline gate), mirroring how mod 160 shares
   `missing_standard_files` / `unreachable_docs`. Guards: if `plans/design/adrs/`
   is absent it treats the ADR set as empty; if an index file itself is missing,
   staleness stays silent (that miss is already reported by
   `missing_standard_files`), so the two checks never double-report.
