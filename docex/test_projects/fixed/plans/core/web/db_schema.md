# web — db schema

`web` owns the schema of the project's single backing relational database, `db` (postgres 15).

## Tables

### `pings`

Stores each ping created by `POST /pings` until `worker` processes it.

| Column | Type | Notes |
| ------ | ---- | ----- |
| `id` | `uuid` | Primary key. Generated by `web` at write time (`uuid7` for time-ordered insertion). |
| `payload` | `text` | The request body, stored verbatim as a string. Schema is intentionally not validated past "it's a string" — keeps domain surface trivial. |
| `created_at` | `timestamptz` | Defaults to `now()`. |
| `processed_at` | `timestamptz` | `NULL` until `worker` claims and processes the row; set to `now()` at that point. |

### `schema_migrations` (managed by dbmate)

Maintained automatically by dbmate; lists applied migration filenames. Not application-visible.

## Migrations

All migrations live at `core/web/migrations/*.sql` and are versioned by timestamp prefix per dbmate's convention. The first migration creates the `pings` table; subsequent migrations evolve it.

Doctrine requirement: migrations are idempotent and reversible (`databases.md`). Each migration file declares both `-- migrate:up` and `-- migrate:down`.
