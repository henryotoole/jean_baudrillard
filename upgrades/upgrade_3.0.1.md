# Upgrading to doctrine 3.0.1

Two small `docex docs` changes; see the
[3.0.1 CHANGELOG entry](../CHANGELOG.md). No `infra.yml`, CICL, contract, or
deployed-infrastructure change — nothing to recompile or redeploy.

1. **`docs overhead` / `docs cxt_groups`** no longer follow the outbound links
   of an L1 standard root (a router file), so overhead no longer fans out across
   the whole design corpus when a root is the subject. This affects only the
   doc-refine tooling's context grouping — **no project action.**
2. **`docs adr`** now renders the ADR index with a bare `ADR ID` column plus a
   separate `Link` column, where the `ADR ID` cell used to be the link itself.
   This changes the generated bytes of `adr_index.md` / `adr_active.md`, so a
   project's committed ADR indexes must be regenerated — otherwise
   `docs check`'s freshness gate reports them stale.

## Machine sync

Run the **`doctrine-update`** skill (or by hand): `git pull` in
`~/.claude/jean_baudrillard`, then `bash setup.sh`. That builds `docex:3.0.1`
(`docex` source changed: `docs/adr.py`, `docs/overhead.py`) and regenerates
`RESIDENT.md` — the resident-stratum file `doctrine/infrastructure/docex.md`
changed wording in both the `overhead` and `adr` command descriptions, and
`doctrine/practices/docs.md` changed one line, so expect a small resident diff.
The shim is unchanged from 3.0.0.

## Project upgrade

### 1. Repin

```bash
bash ~/.claude/jean_baudrillard/docex_install.sh .
```

Writes `docex_version: 3.0.1` into `project.yml`. Idempotent.

### 2. Regenerate the ADR indexes

```bash
./bin/docex docs adr
```

This rewrites `plans/design/adr_index.md` and `adr_active.md` into the new
two-column form. Run it in **every** project that has a `plans/design` tree (the
header changed too, so even a project with no ADRs has a stale header row until
this runs). Idempotent; commit the regenerated files.

No recompile or redeploy is required — nothing in this release changes emitted
infrastructure.
